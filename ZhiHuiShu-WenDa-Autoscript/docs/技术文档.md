## 1. 项目概述

### 1.1 这是什么

一个浏览器用户脚本（UserScript），在智慧树（zhihuishu.com）课程问答页自动运行，用 AI 大模型自动完成课程问答的"平时分"任务：

- **回答模式（默认）**：自动找到未回答的题目 → 新开后台标签页 → AI 生成简短回答 → 自动发布 → 关闭标签页 → 回到列表继续下一题。达到目标条数后自动暂停。
- **提问模式**：按倒计时自动点击"提问"按钮 → 打开提问弹窗 → AI 生成不重复的问题 → 自动点击"立即发布" → 进入下一轮倒计时。

### 1.2 核心特性一览

| 特性 | 说明 |
| --- | --- |
| 父子页面分工 | 列表页（父）负责指挥调度，详情页（子）只负责答题并汇报，避免重复启动 |
| 题目三状态记忆 | 未回答（红）/ 已回答（绿）/ 无法回答（橙色删除线），持久化到本地存储 |
| 官方记录同步 | 启动时自动读取"我参与的 → 我的回答"官方清单，把答过的题直接标记，无需逐个点开 |
| 全自动提问 | 提问模式下 AI 生成问题并自动发布，生成时会参考最近 20 题防止重复 |
| 二维码验证处理 | 检测到安全验证二维码自动暂停并提醒，人工验证后自动继续 |
| 可拖拽悬浮面板 | 蓝白简洁风、可折叠、位置记忆、防飞出屏幕 |
| 问题管理弹窗 | 按课程分 Tab 查看/搜索/修改题目状态，支持分页与批量设置 |
| 目标自动暂停 | 达到回答/提问目标条数即自动暂停 |
| 官方数据统计（实验性） | 可选以页面"我的参与"官方数字判断目标，连续 N 轮无变化只提醒，**不再自动刷新页面** |
| 版本自动检查 | 每小时最多一次，从 ScriptCat 拉取最新版本号显示在面板 |

### 1.3 技术栈

| 项 | 说明 |
| --- | --- |
| 语言 | 纯原生 JavaScript（ES6+），无构建步骤，单文件 IIFE 包裹 |
| 运行环境 | Tampermonkey / ScriptCat 等支持 GM 系列 API 的用户脚本管理器 |
| 页面交互 | DOM 选择器 + MutationObserver + Vue 2 组件实例数据（`__vue__.$data`） |
| 跨标签通信 | GM_setValue / GM_addValueChangeListener（脚本管理器本地存储） |
| 网络请求 | GM_xmlhttpRequest（绕开页面 CSP，脚本管理器上下文发起） |
| AI 接入 | 任意 OpenAI Chat Completions 兼容接口 |

### 1.4 关键设计决策（为什么这样设计）

| 决策 | 原因 |
| --- | --- |
| 为什么详情页是"子页面"模式 | 详情页由脚本新开标签打开，若照常跑父页面启动逻辑，会再次触发"同步→跳题→倒计时→又开新标签"的死循环。子页面模式启动时直接拦截，只做回答。 |
| 为什么用 `GM_openInTab` 而不是直接 `span.click()` | 页面题目点击走的是 `window.open`，脚本合成的点击不是用户手势，会被浏览器弹窗拦截器拦掉。脚本临时替换 `window.open` 截获真实 URL，再用 `GM_openInTab`（不受弹窗拦截）后台打开。 |
| 为什么不直接调官方 API 拉"我的回答" | 智慧树问答接口的请求参数是 AES 加密的，外部无法直接构造请求。但"我的回答"页面的 Vue 组件数据里有完整清单，脚本跳过去读一遍再跳回来即可（hash 路由切换不刷新页面，脚本上下文不中断，已实测验证）。 |
| 为什么列表里有些题标"无法回答" | 平台对部分题目（内容含下划线填空等）不提供回答入口，AI 也答不了。脚本用一组正则识别这类题（"什么是…""…是什么""…好不好"等句式），直接标为"无法回答"并跳过，避免浪费时间点开。 |
| 为什么发布提问后不检测发布结果 | 平台发布反馈弹窗不稳定，等待检测会造成流程卡死。改为点完"立即发布"立即计数并进入下一轮倒计时。 |

## 2. 安装与环境要求

### 2.1 环境要求

| 项 | 要求 |
| --- | --- |
| 浏览器 | Chrome / Edge / Firefox 等 Chromium 或 Gecko 内核现代浏览器 |
| 脚本管理器 | ScriptCat（脚本猫）或 Tampermonkey（油猴），推荐 ScriptCat |
| 匹配站点 | `*://*.zhihuishu.com/*`（@match 已内置） |
| 网络 | 能访问所选 AI API 地址（默认 `https://api.gpt.ge`） |

### 2.2 安装步骤

1. 浏览器安装脚本管理器扩展（ScriptCat / Tampermonkey）。
2. 新建脚本，把 `zhihuishu-qa-automation.user.js` 全文粘贴进去，保存。
3. 登录智慧树，进入任意课程的"课程问答"页（URL 形如 `https://qah5.zhihuishu.com/qa.html#/web/home/<课程ID>?recruitId=...&role=2`）。
4. 页面右侧出现悬浮面板即安装成功。

### 2.3 首次使用配置

> **重要：脚本不内置任何 API Key。** 你需要在面板里填入自己的 Key 才能使用 AI 功能。
> Key 仅保存在本机脚本管理器存储（`GM_setValue`）中，不会上传，也不会进入 Git 仓库。

1. 展开面板底部"**API 与参数设置**"。
2. 在 **API Key** 框粘贴你自己的 Key（必填，密码框显示）。
3. 在 **供应商 / API 地址** 下拉中选择服务商：
   - GPT.GE 中转（默认）
   - DeepSeek 官方
   - OpenAI 官方
   - 智谱 BigModel
   - 阿里通义 DashScope
   - 任意 OpenAI 兼容的「自定义地址…」（需以 `/chat/completions` 结尾）
4. 选择模型（默认 `glm-4-flash`，可自定义添加）。
5. 设置回答目标（默认 50）、脚本安全上限（默认 100）与提问目标（默认 10）。
6. 点击"**保存设置**"。面板会显示"✓ 已配置 API Key"确认状态。
7. 未填 Key 时运行，脚本会提示"尚未配置 API Key"并自动展开设置区、聚焦输入框，不会发出空请求。

### 2.4 日常使用流程（回答模式）

1. 打开课程问答页 → 脚本自动同步官方"我的回答"（约几秒钟，有提示）。
2. 列表里绿色=已答、橙色删除线=无法回答、红色=未答；脚本自动跳到第一道红色题并开始倒计时。
3. 倒计时结束 → 后台新开标签答题 → 答完子页面汇报并自动关闭 → 父页面进入下一轮倒计时。
4. 达到目标条数 → 面板显示"回答目标已达成 ✓"并自动暂停。

## 3. 整体架构设计

### 3.1 单文件结构总览

整个脚本是一个 IIFE（立即执行函数表达式），内部按功能分区，函数声明全部提升（hoisting），因此调用顺序不受定义位置影响：

```
(function () {
    'use strict';
    ├── 常量与全局状态变量
    ├── 父子页面分工（isDetailPage / reportToParent / handleChildReport）
    ├── 现代化样式（injectStyles）
    ├── Toast 提示（showAlert）
    ├── 悬浮主面板（createPanel / updatePanel / ensurePanel / 回归按钮 / 事件绑定）
    ├── 问题管理弹窗（createQuestionManagementModal 等）
    ├── 工作模式引擎（onWorkTick / startCountdown / pauseForTarget / 停滞检测）
    ├── 回答模式流程（clickTheUnansweredLink / waitForAnswerButton / startChecking / answerQuestion ...）
    ├── 提问模式流程（findAskEntry / runAskCycle / autoPublishQuestion / generateQuestion ...）
    ├── 二维码处理（handleCaptcha）
    ├── 同步模块（syncAnsweredFromMyJoin / readMyJoinData / applyAnsweredSync）
    ├── 滚动 / MutationObserver / 版本检查
    └── 启动入口（window.onload 按页面类型分流）
})();
```

### 3.2 父子页面架构（核心）

智慧树问答页是 Vue 2 单页应用（hash 路由），关键路由：

| 路由 | 角色 | 脚本行为 |
| --- | --- | --- |
| `#/web/home/<课程ID>` | **父页面** | 完整功能：同步 → 跳题 → 倒计时 → 开子页面 |
| `#/web/questionDetail/<课程ID>/<题目ID>` | **子页面** | 只做：找"我来回答" → AI 答题 → 发布 → 汇报 → 关闭自己 |
| `#/web/myJoin/<课程ID>?type=answer` | 临时同步页 | 父页面短暂跳过去读数据，读完跳回 |

判定函数：

```js
const DETAIL_HASH_PATTERN = /#\/web\/questionDetail\/\d+/;
function isDetailPage() { return DETAIL_HASH_PATTERN.test(location.hash); }
```

**启动分流（`window.onload`）**：

```
onload
 ├─ 是详情页？──→ 子页面模式：监控面板 + initMutationObserver + waitForAnswerButton，直接 return
 ├─ 曾是被关闭失败的子页面（sessionStorage.zhsWasChild）？──→ 优先 window.close() 自杀
 └─ 父页面模式：waitForAnswerButton（防御性）+ initMutationObserver
      └─ 等官方"我参与的"数字渲染（≤10 秒）
           ├─ 当前模式官方数已达标 ──→ 提示"已达标，脚本不再运行"，结束
           └─ 未达标 / 读不到
                ├─ 回答模式：等课程名 → syncAnsweredFromMyJoin → startWork(onWorkTick)
                └─ 提问模式：直接 startWork(onWorkTick)
```

主循环为固定节奏：**5 秒倒计时 → 答一题 → 挂起等子页面汇报 → 收到汇报再 5 秒倒计时 → 下一题**。

### 3.3 父子通信协议

子页面答完通过 GM 存储向父页面发消息：

| 项 | 值 |
| --- | --- |
| 存储键 | `zhsAnswerReport` |
| 数据格式 | JSON 字符串：`{ ts: 毫秒时间戳, question: 题目文本, status: 状态描述, version: 脚本版本, officialAnswer?: number, officialAsked?: number }` |
| 发送方 | 子页面 `reportToParent(questionText, status, extra)` |
| 接收方 | 父页面 `handleChildReport()`，双保险：<br>① `GM_addValueChangeListener` 变更监听（即时）<br>② `startCountdown` 的每秒 tick 里轮询兜底 |

父页面收到汇报后：弹 Toast（"子页面反馈：「题目前20字…」已回答"）并刷新面板进度。`lastReportTs` 内存变量去重，旧消息不会重复弹。父页面处于等待状态时（`waitingForChild`），收到汇报还会自动恢复下一轮倒计时（见 5.8 工作引擎）。

#### 3.3.1 子页面官方数字回传（v3.1.0 新增）

**背景**：子页面（题目详情页）每次打开时，页面上**就有**官方的「我的回答」数据——它来自官方接口，比父页面列表页的数字更新、更权威。例如父页面还显示 46，子页面已经是 49。

**做法**：子页面在答题完成汇报时（两个汇报点都覆盖：正常答完、以及"原本已答过"），读一次自己的 `.MyParticipatory-div`，把数字放进 `officialAnswer` / `officialAsked` 一起发给父页面。父页面**完全采信**这个值。

**父页面合并规则**（`applyChildOfficial`，v3.3.0 起为单调递增）：

| 情况 | 处理 |
| --- | --- |
| 子页面数字 **大于** 当前已采信值 且 **大于** 父页面当前值 | 采用（以子页面官方数据为准） |
| 子页面数字 ≤ 当前已采信值 | 忽略（**只升不降**，防止偶发读到旧值把进度拖回去） |
| 父页面自身数字更大 | 保持父页面值 |
| 值为 undefined / NaN / 非数字 | 忽略，不清空已有值 |

校正值存在内存变量 `childOfficialOverride`，由 `readOfficialCounts()` 统一合并。因此**所有调用方**（目标判断 `isTargetReached`、面板进度 `updatePanel`、启动门槛 `gate`）都会自动用上较新的官方数字，无需逐处修改。

> 实现细节：比较基准取 `max(已采信值, readOfficialCountsRaw())`。必须用 `readOfficialCountsRaw()`（纯 DOM 值）而非 `readOfficialCounts()`——后者已经合并过校正值，会导致"父页面追上后同值被误判为无变化"，校正值再也无法推进。

#### 3.3.2 停止条件：双保险（v3.3.0）

脚本判断"是否该停"统一走 `isTargetReached()`，满足任一即停：

| # | 条件 | 依据 | 说明 |
| --- | --- | --- | --- |
| ① | 官方「我的回答」**≥** 回答目标（默认 50） | 权威 | 官方数字含子页面回传值 |
| ② | 本次脚本已答 **≥** 安全上限（默认 100，可设置） | 兜底 | 官方数字迟迟不涨时防止无限刷 |
| ③ | 官方数字完全读不到 | 退化 | 退回内部记录数 `getAnsweredCount()` 判断 |

强调：**脚本计数不再参与"目标是否达成"的判断**，它只负责第 ② 条安全上限。面板显示为 `已答 X / 50`（官方）与 `本次 Y/100`（脚本参考值）。

停止原因的文案由 `describeStopReason()` 统一生成，会明确区分是官方达标还是撞到安全上限，例如：

- `已停止：官方「我的回答」已达 50/50`
- `已停止：脚本计数已达安全上限 100 题（官方显示 46）`

### 5.3.1 子页面监控 UI（v2.4.0 新增）

子页面（详情页）左下角注入 `#zhsChildPanel` 小面板（`.zhs-child-panel`），仅在详情页创建：

| 区块 | 内容 |
| --- | --- |
| 题目卡片 `.zhs-child-q` | 从 `.question-content span` 读取的本题全文，随轮询自动更新 |
| 状态行 `.zhs-child-status` | 当前阶段文字 + 状态点：蓝=进行中、橙=等待（AI/二维码/发布）、绿=完成、红=出错 |
| AI 回答卡片 `.zhs-child-answer` | AI 返回答案全文（超过 300 字截断），填入编辑器后显示 |
| 操作日志 `.zhs-child-log` | 带时间戳（HH:MM:SS）的流水，保留最近 30 条，成功绿色/失败红色 |

状态流转：寻找"我来回答" → 点击后等编辑器 → 编辑器就绪 → 已向 AI 请求/等待 AI 回答 → 答案已填入准备发布 → 点击"立即发布" → 回答完成关闭页面；遇到二维码插入"等待人工验证/验证完成"；AI 失败显示红色并记录，下轮自动重试。

### 3.4 主工作循环（父页面）

```
startCountdown(min~max 秒随机)
   │ 每秒 tick：更新面板、轮询子页面汇报
   ▼ 倒计时归零
onWorkTick()
   ├─ 正在同步官方记录？→ 跳过本轮
   ├─ 有二维码弹窗？→ 提醒人工验证，重启倒计时，跳过本轮
   ├─ 目标已达成？→ 清除倒计时、提示、暂停
   ├─ 开启官方数据实验功能？→ 停滞检测（连续 N 轮无变化只弹提醒，不刷新页面）
   ├─ 回答模式：clickTheUnansweredLink() + startCountdown()
   └─ 提问模式：runAskCycle()
```

回答模式的完整一轮：

```
父页面倒计时归零
  → clickTheUnansweredLink：从 DOM 列表找第一个"未回答"状态的题
  → openQuestionInNewTab：截获 window.open 真实地址，GM_openInTab 后台开子页面
  → 父页面进入等待状态（beginChildWait）：暂停一切动作，显示"等待子页面回答…"，
    同时启动 150 秒兜底超时
子页面（后台标签）
  → waitForAnswerButton：找"我来回答"按钮并点击
  → startChecking（每 2 秒轮询）：
       输入框为空 → answerQuestion（调 AI API）→ 填入答案
       输入框有内容 → startPublishChecking → 点"立即发布"
       "我来回答"按钮消失 → 视为发布成功 → markQuestionAsAnswered
       → reportToParent（汇报）→ closeDetailWindow（关闭自己）
父页面收到汇报 → Toast 提示 + 面板进度 +1 → 恢复倒计时 → 到点继续下一题
（若 150 秒未收到汇报：超时自动恢复倒计时，避免永久挂起）
```

## 4. 核心概念

### 4.1 题目三状态

| 状态 | 列表显示 | 含义 | 对回答模式的影响 |
| --- | --- | --- | --- |
| `未回答` | 红色文字 | 还没做过 | 倒计时结束后会被点开回答 |
| `已回答` | 绿色文字 | 已完成 | 自动跳过（不计时） |
| `无法回答` | 橙色 + 删除线 | 平台不允许答 / AI 答不了的句式 | 自动跳过（不计时），不计入回答目标 |

状态持久化在 `questionsData`（GM 存储），按**课程名**分组、以**题目完整文本**为键。

状态流转规则：

- `checkHomeRegex`：列表中出现的新题 → 登记为 `未回答`（已存在不覆盖）。
- `addQuestionStatus`：命中无效问题正则且当前不是 `已回答` → 置为 `无法回答`；**不会把 `已回答` 降级**。
- `applyAnsweredSync`：官方"我的回答"清单中的题 → 置为 `已回答`（覆盖 `未回答` 与 `无法回答`，因为人工已答的题算完成）。
- `markQuestionAsAnswered`：子页面发布成功后，若当前是 `未回答` → 置为 `已回答`。
- 管理弹窗里可手动改为 `已回答` / `未回答`。

### 4.2 无效问题识别正则

位于 `addQuestionStatus`：

```
/什么是.+/, /.+是什么/, /.+是什么意思/, /.+的含义/, /指什么/,
/是不是/, /对不对/, /好不好/, /好吗/, /近吗/, /远吗/, /对吗/,
/可以吗/, /可以.+吗/, /是否可以/, /有没有/, /能不能/, /应该.+吗/,
/是否应该/, /必须.+吗/, /是否必须/, /需要.+吗/, /是否需要/, /一定.+吗/,
/是否一定/, /是否合理/, /是否相同/, /是否不同/,
/有意义吗/, /意义大吗/, /喜欢.+吗/, /如何翻译.+/
```

任何一条命中即视为无法回答。扩展时请保持"命中即跳过"的保守原则。

### 4.3 目标达成判断

```js
function isTargetReached() {
    // 页面“我参与的”官方数字（回答模式取“我的回答”，提问模式取“我的提问”）
    // 能读到时，始终以官方为准；
    // 读不到（栏目未加载/站点改版）才退回脚本内部统计
    //   回答模式：questionsData 中本课程状态为"已回答"的题数
    //   提问模式：askedQuestions 中本课程已记录的提问条数
}
```

另外在**启动门槛**（见 5.17）还会先做一次同样的官方达标检查：本课程当前模式已达标则脚本直接不运行（提示"已达标，脚本不再运行"），未达标才进入同步与答题循环。默认目标：回答 50 条、提问 10 条。

### 5.7 问题管理弹窗（`createQuestionManagementModal`）

- 从面板"管理答题列表"打开；重复打开先移除旧实例。
- **课程 Tab**：每个有记录的课程一个 Tab，激活状态记 GM `lastViewedCourseIndex`。
- **表格**：题目（含搜索框，搜索时标注"第 N 页"）、状态（绿/橙/红三色标签）、操作（设为已答/设为未答）。
- **分页**：每页条数可调（GM `questionsPerPage`，默认 10），页码按课程记忆（`lastViewedPage_<课程名>`），支持上一页/下一页/输入页码跳转。
- **批量操作**："一键本页已答 / 一键本页未答"（`setQuestionsStatusForCurrentPage`）。
- 任何修改后 `refreshQuestionManagementModal`：重建弹窗 + `updatePanel`。

### 5.8 工作模式引擎

#### 5.8.1 倒计时（`startCountdown(restartCount = null)`）

- 倒计时时长**固定 5 秒**（v2.5.0 起不再允许用户调节，`countdownMin/Max` 设置项已移除）。
- `restartCount` 不为 null 时沿用传入值（暂停后继续的场景），否则从 5 秒开始。
- 写入 GM `countdownTime`（本轮总时长）与 `currentCountdown`（当前剩余，供面板显示与暂停恢复）。
- 每秒 tick：剩余 -1 → 更新面板 → `handleChildReport()` 轮询子页面汇报 → 归零时清定时器并 `onWorkTick()`。

#### 5.8.2 工作节拍（`onWorkTick`）

按优先级短路：

1. `syncingAnswered` 为真 → 本轮跳过（同步期间不工作）。
2. `waitingForChild` 为真（已开子页面、正等待其汇报）→ 本轮跳过，直到收到汇报或 150 秒超时恢复。
3. 页面存在 `.yidun_modal`（安全验证二维码）→ 每 60 秒最多弹一次提醒，重启倒计时，跳过本轮。人工验证后弹窗消失，下一轮自动恢复工作。
4. `isTargetReached()` → `pauseForTarget`：清倒计时 + 提示 + 暂停。
5. 官方数据实验功能开启时：与上次快照比对，连续 N 次（`stagnantLimit`，≥2）作答后官方数字无变化 → **只弹一次提醒**（60 秒内不重复），不刷新页面，等人工核对（v3.0.0 起）。
6. 分模式执行：回答模式 `clickTheUnansweredLink()`，成功打开子页面则 `beginChildWait()` 挂起等待（未找到未答题则直接重启倒计时）；提问模式 `runAskCycle()`。

#### 5.8.3 目标暂停（`pauseForTarget`）

清除倒计时定时器、弹 Toast、控制台记录、刷新面板。之后用户可点"继续"手动恢复。

### 5.9 回答模式流程

#### 5.9.1 找题与开子页面（`clickTheUnansweredLink`）

- 遍历 `.question-item`，读取每题 `.question-content span` 的 `title`（题目全文）与 GM 状态，**只收集 `status === "未回答"` 的题**。
- 取第一道未答题 → `openQuestionInNewTab(span)`。
- 没有未答题时仅打印日志（配合"自动滚动"加载更多题）。

#### 5.9.2 绕过弹窗拦截（`openQuestionInNewTab`）

```js
// 1. 备份并重写 window.open，记录 URL
// 2. 对题目 span 执行 click()（页面自己的事件处理器会调用 window.open）
// 3. 恢复原始 window.open
// 4. 用 GM_openInTab(targetUrl, { active: false }) 后台打开
```

`{ active: false }` 保证不抢用户当前标签的焦点。若未截获到地址（页面结构变更），打印警告，本轮不打开。

#### 5.9.3 子页面答题主循环（`waitForAnswerButton`）

每 `intervalTime`（默认 2 秒）轮询，两种结局：

**A. 找到"我来回答"按钮**（`div.my-answer-btn.ZHIHUISHU_QZMD.tool-show span` 且文本为"我来回答"）：
- 点击按钮 → 等待文本框（`textarea`）出现 → 进入 `startChecking()`。
- 注意：若已答过的题，平台不显示该按钮，走分支 B。

**B. 连续两次找不到按钮**（`noAnswerButtonCount > 1`）且当前是详情页：
- 读取题目文本 → `markQuestionAsAnswered`（状态从"未回答"改"已回答"）→ 子页面则 `reportToParent(questionText, "已回答（原本已答过，直接关闭）")` → `closeDetailWindow()`。
- 该分支同时覆盖"AI 答案发布成功后按钮消失"的正常收尾（此时状态已被置为已回答，`markQuestionAsAnswered` 幂等）。

#### 5.9.4 发布监控（`startChecking`，每 2 秒）

| 检查项 | 处理 |
| --- | --- |
| 题目/输入框不存在 | 跳过本轮 |
| 出现二维码弹窗 | `handleCaptcha()`，暂停等待人工验证 |
| "我来回答"按钮消失 | 视为发布成功 → 标记已回答 → 子页面汇报 → 关闭窗口 |
| 输入框已有内容 | `startPublishChecking()`：发布按钮（`.dialog-bottom .up-btn.ZHIHUISHU_QZMD.set-btn` 且文本"立即发布"）存在则点击 |
| 输入框为空 | `requestLock` 防重入 → `answerQuestion()` 调 AI |

#### 5.9.5 AI 答题（`answerQuestion`）

- `GM_xmlhttpRequest` POST 到 `API_URL`，OpenAI Chat Completions 格式。
- Prompt 设计：要求 30 字以内简介、纯文本无 Markdown、禁止出现"学习通"字样、至少 10 个字。
- 成功：解析 `choices[0].message.content` → 写入 textarea → 派发 `input` 事件（触发 Vue 双向绑定）→ 下一轮 tick 自动点发布。
- 失败：解锁 + Toast，下个 tick 重试。

#### 5.9.6 关闭与自杀（`closeDetailWindow`）

1. 立即 `window.close()`（GM_openInTab 打开的通常可关）。
2. 800ms 后若还在（`setTimeout` 已排队，页面若已关闭则代码不会执行）：
   - `sessionStorage` 写入 `zhsWasChild = '1'` 标记"我是没死成的子页面"；
   - hash 退回问答首页。
3. 退回首页后脚本重新加载，`window.onload` 检测到 `zhsWasChild` → 清除标记 → 再次 `window.close()` 尝试自杀，避免成为第二个父页面并行答题。实在关不掉才作为正常父页面运行。

### 5.10 提问模式流程（全自动）

#### 5.10.1 找入口（`findAskEntry`）

两级策略：
1. 优先 `div.ask-btn[title="提问"]`（页面右下角纯图标按钮，实测 48×48）；
2. 兜底按文字找"提问 / 我要提问 / 提个问题"（排除脚本自己的面板与提问弹窗内的元素）。

#### 5.10.2 提问周期（`runAskCycle`）

`askLock` 防重入。流程：

```
findAskEntry 找不到 → 提示 + 本轮跳过（重启倒计时）
simulateClick(入口) → 每 0.5 秒等提问弹窗（findAskDialog），最多 20 次（10 秒）
弹窗出现 → generateQuestion(dialog, { onSuccess, onFail })
  ├─ onSuccess(question) → autoPublishQuestion(dialog, question)
  │     每 0.6 秒找"立即发布"按钮，最多 12 次（7.2 秒）
  │     找到 → 点击发布 → recordAsked(question) 计数 → askLock=false → startCountdown()
  │     （刻意不检测发布结果，避免平台反馈弹窗造成卡死）
  └─ onFail → 解锁 + 重启倒计时
等待超时 → showAskManualHint()：提示用户手动点一次「提问」，并开始监听接管
```

#### 5.10.2.1 首次点不开提问框的问题（v3.2.0）

**现象**：刷新页面后第一次提问，脚本无法自动打开提问框；只要用户手动点开过一次，之后都能自动跑。

**原因**：站点的「提问」按钮对点击事件有更严格的要求。原来的 `entry.click()` 只派发一个 `click` 事件，站点若绑定了 `pointerdown` / `mousedown` / `mouseup` 或依赖按下-抬起状态，就收不到完整交互。

**处理**：

1. **`simulateClick(el)`**：按真实指针交互顺序发一串事件
   `pointerover → pointerenter → mouseover → mouseenter → pointerdown → mousedown → focus → pointerup → mouseup → click → 原生 click()`。
2. **`findAskDialog()`**：弹窗定位由严格选择器改为三级降级，避免"弹窗其实开了但缺 `aria-modal` 导致判为未打开"：
   - `div[role="dialog"][aria-modal="true"][aria-label="提问"].el-dialog`（严格）
   - `div[role="dialog"][aria-label="提问"]`（缺 aria-modal）
   - 可见的 `.el-dialog` 且内部有 `textarea`
3. **手动兜底**：若 10 秒内仍未打开，面板操作区出现「👉 手动唤起提问框」按钮，同时脚本以 400ms 轮询监听——用户点开弹窗后脚本自动接管（生成问题 → 发布），不需要用户再管。

> 局限说明：浏览器禁止脚本伪造 `isTrusted === true` 的用户手势，若站点处理函数里显式检查 `event.isTrusted`，任何脚本都无法自动点击，只能由用户手动点一次。第 3 步就是为这种情况准备的。

#### 5.10.3 AI 生成问题（`generateQuestion`）

- 收集列表最近 20 道题文本（`.question-content.ZHIHUISHU_QZMD span`）作为"避重参考"。
- Prompt 要求：针对课程名、与参考题**完全不同**的开放式问题、50 字以内、发散句式（不要一直"如何…"）、只输出一个问题。
- `temperature: 1, top_p: 1`（提高随机性，进一步防重复）。
- 成功：填入弹窗 textarea 并派发 `input` + `change` 事件 → 回调 `onSuccess`。
- 手动模式：提问弹窗底部由 MutationObserver 自动插入"✨ AI 生成问题"按钮（`#generateQuestionButton`），点击同样走 `generateQuestion`（无回调）。

### 5.11 同步官方"我的回答"模块

#### 5.11.1 为什么要这个模块

问答列表接口**不返回**"我是否答过该题"的标记（实测列表数据只有回答数、围观数等）。但"我参与的 → 我的回答"页面（hash 路由 `#/web/myJoin/<课程ID>?...&type=answer`）的 Vue 组件 `.my-join-container` 的 `$data` 中有完整的已答题目列表（单页 50 条，`noMore === true` 即全部加载完，实测 46 条一次读完）。

#### 5.11.2 同步流程（`syncAnsweredFromMyJoin(courseName, done)`）

```
设置 syncingAnswered = true（期间 onWorkTick 一律跳过）
├─ 已在 myJoin 页？直接采集
└─ 否则：location.hash 跳转到 myJoin（type=answer）
   collect()：每 0.5 秒轮询 readMyJoinData()，直到 (noMore && !loading) 或 20 秒超时
   applyAnsweredSync()：把 questionContent 逐条写入 questionsData[课程名][题] = "已回答"
   Toast 汇报新增条数
finish()：hash 跳回 #/web/home/<课程ID>（保留 recruitId/role 参数）
   每 0.5 秒等首页 .question-item 渲染出现（最多 15 秒）→ 执行 done 回调
```

关键实测结论：**hash 路由切换不会刷新页面**，脚本上下文、定时器全部存活，因此"跳过去→读数据→跳回来"全程无缝。

课程名兜底：列表页 `.course-name` 可能暂时为空，此时取数据项自带的 `courseName` 字段。

#### 5.11.3 触发时机

| 时机 | 行为 |
| --- | --- |
| 父页面启动（回答模式） | 等课程名出现（最多 8 秒）→ 自动同步一次 → 才开始工作 |
| 面板"同步已答"按钮 | 手动随时同步（中途用手机答了几道后点一下即可） |
| 提问模式 | 不同步（与回答无关） |
| 子页面 | 被启动分流拦截，永不触发同步 |

### 5.12 二维码（安全验证）处理（`handleCaptcha`）

- 触发：检测到 `.yidun_modal` 元素（易盾安全验证）。
- `captchaHandling` 防重入。系统通知（`GM_notification`）+ Toast 提醒人工验证。
- 每 2 秒轮询：弹窗消失 → 提示"验证完成"并自动继续答题。
- 5 分钟超时 → 关闭当前窗口（子页面）避免永久卡死。

### 5.13 列表状态染色（`addQuestionStatus`）

- 遍历 `.question-item`，按 GM 状态染色：未回答→红、已回答→绿；命中无效正则且非已回答→橙色删除线并写回"无法回答"。
- 由 `initMutationObserver` 的防抖回调驱动（DOM 变化 500ms 后执行），列表翻页/加载新题时自动应用。

### 5.14 滚动模块（`scrollToLastUnansweredQuestion`）

- 找第一个"未回答且未排除（无删除线）"的题，在 `.el-scrollbar__wrap` 容器内平滑滚动到它；200ms 轮询确认到位，5 秒超时兜底。
- 没找到 → 滚到底部并派发 scroll 事件触发平台无限加载 → 每秒检查题数是否增加，10 秒内出现新题则重新查找。
- `scrolling` 防重入。

### 5.15 MutationObserver（`initMutationObserver`）

监听整个 body 的 attribute/childList/characterData 变化，500ms 防抖后执行：`addQuestionStatus()` →（若开启）自动滚动 → `checkHomeRegex()`。

> 注意：提问弹窗的"AI 生成问题"按钮由另一个**独立**的 MutationObserver（`checkAndAddGenerateQuestionButton`）维护，该观察者在脚本加载时即启动，与子页面/父页面分流无关。

### 5.16 版本检查（`checkForLatestVersion`）

- 每小时最多一次 `GM_xmlhttpRequest` 拉取 ScriptCat 上脚本 meta.js，正则提取 `@version`。
- 失败重试最多 5 次（间隔 1 秒）；面板"最新版"字段展示结果。

### 5.17 启动入口（`window.onload`）

分流顺序（详细流程图见 3.2）：

1. 注入样式；
2. **详情页** → 子页面模式，return；
3. **带 `zhsWasChild` 标记**（自杀失败的子页面退回）→ 清除标记，优先 `window.close()`；
4. 回答模式 → `waitForAnswerButton()`（防御性，正常父页面无回答按钮会自然走"计数→不关闭→清零"分支）；
5. `initMutationObserver()`；
6. **启动门槛**：最多等 10 秒官方"我参与的"数字渲染 → 当前模式官方数已达标则提示"已达标，脚本不再运行"并保持暂停；未达标（或读不到）才继续；
7. 回答模式 → 等待课程名 → 同步官方已答 → `onWorkTick()` 立即工作一轮（跳题不计时，跳到未答题才开始 5 秒倒计时）；提问模式 → 直接 `onWorkTick()`。之后节奏固定为：5 秒倒计时 → 答一题 → 挂起等汇报 → 再 5 秒。

## 6. 关键机制深入剖析

### 6.1 并发控制锁一览

| 锁 | 类型 | 保护范围 |
| --- | --- | --- |
| `requestLock` | 内存布尔 | AI 答题请求同一时刻只有一个 |
| `askLock` | 内存布尔 | 提问周期不重叠（等弹窗/等发布期间不重复进入） |
| `syncingAnswered` | 内存布尔 | 同步官方数据期间 `onWorkTick` 一律跳过 |
| `captchaHandling` | 内存布尔 | 二维码处理不重复触发 |
| `scrolling` | 内存布尔 | 滚动操作不重叠 |
| `waitingForChild` | 内存布尔 | 父页面已开子页面、等待汇报期间不启动新动作（配 150s 超时兜底） |
| GM `currentCountdown` | 持久化 | 暂停/继续跨标签恢复倒计时 |
| 单例 DOM | DOM 存在性检查 | 样式 `#zhs-style`、面板 `#zhsPanel`、按钮 `#zhsRestoreBtn`/`#generateQuestionButton`、弹窗 `.question-management-modal` 全部幂等 |

### 6.2 防死循环设计

| 场景 | 机制 |
| --- | --- |
| 子页面重复启动父流程 | `isDetailPage()` 启动分流，子页面直接 return |
| 子页面关不掉退回首页变"第二个父页面" | `sessionStorage zhsWasChild` 标记 + 重新加载后优先自杀 |
| AI 请求重试风暴 | `requestLock`；API 失败只解锁不连锁触发 |
| 提问弹窗一直不出现 | `runAskCycle` 20 次×0.5s 上限后放弃本轮 |
| 发布按钮一直不出现 | `autoPublishQuestion` 12 次×0.6s 上限后放弃本轮 |
| 二维码无人验证 | 5 分钟超时强制关闭子页面 |
| 同步数据读取卡死 | collect 20 秒超时；finish 等列表渲染 15 秒超时 |
| 滚动监听卡死 | 5 秒到位超时 + 10 秒等新题超时 |

### 6.3 Vue 页面数据读取技巧

本脚本没有逆向任何加密接口，而是直接读取页面 Vue 组件的响应式数据：

```js
const v = document.querySelector('.qa-list-container').__vue__;      // 列表页
const v = document.querySelector('.my-join-container').__vue__;     // 我的参与页
const list = v.$data.questionList;   // 数组：题目对象
// 列表题目字段：questionId / content / answerNum / userDto ...
// 我的回答字段：questionContent / answerContent / courseName / aid ...
// 分页状态：pageIndex / pageSize / loading / noMore
```

优点：数据即页面真实数据，无需处理加密参数；缺点：依赖页面内部结构，站点改版可能失效（失效表现为同步返回 0 条，此时脚本自动降级为原有"点开才知道"模式，不影响主流程）。

### 6.4 正则路由与 URL 模式

| 模式 | 用途 |
| --- | --- |
| `#\/web\/questionDetail\/\d+` | 判定子页面 |
| `#\/web\/(?:home\|myJoin\|questionDetail)\/(\d+)` | 提取课程 ID |
| `qa.html#/web/home` 前缀 | 判定问答首页（`checkHomeRegex` 登记新题用） |

### 6.5 GM 存储的跨标签特性

- `GM_setValue/GetValue` 存储在脚本管理器本地数据库，**同一脚本的所有标签页共享**——这是父子通信与状态持久化的基础。
- `GM_addValueChangeListener` 在值变化时向其他标签页广播（部分管理器也通知本标签，所以回调里用 `isDetailPage()` 排除子页面自身）。

## 9. 故障排查 FAQ

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 面板没出现 | 不在问答页；或处于"启动即达标/达标暂停"路径（旧版本面板只在倒计时启动时创建，v2.5.1 已修复，任何停止状态都会带重试创建面板） | 确认 URL 含 `qah5.zhihuishu.com/qa.html`；刷新页面；面板找不到时点"📌 自动化助手回归位置" |
| 面板找不到（被拖丢） | 保存的位置在当前窗口外 | 点"📌 自动化助手回归位置"按钮；脚本加载时也会自动重置飞出屏幕的位置 |
| 点击题目没有新标签打开 | 弹窗拦截（旧版问题）/ 页面改版 | 当前版本用 GM_openInTab 已绕开拦截；若仍无效，看控制台"截获详情页地址"日志 |
| 答案生成失败 | API key 欠费/过期；API_URL 不可达；模型名错误 | 面板设置里换 key/地址/模型，保存后等下一轮重试 |
| 一直提示"正在回答问题"但不发布 | AI 接口超时 | 检查网络与 key；失败会自动重试 |
| 题目列表显示红色但点进去已答过 | 官方记录未同步 | 面板点"同步已答"；或刷新页面（启动时自动同步） |
| 详情页一直不关闭 | 浏览器禁止脚本关闭标签 | 脚本会退回首页并自杀重试；如反复出现，检查浏览器扩展权限 |
| 弹出二维码后脚本不动 | 安全验证机制 | 属正常保护：手动完成验证，脚本自动继续（5 分钟超时强制关闭） |
| 达到目标不停 | 官方数据开关打开但页面读不到数字 | 检查"我的参与"栏目数字是否渲染；关闭官方数据开关用内部统计 |
| 提问弹窗没自动操作 | 提问入口按钮改版 | 控制台看"未找到提问入口按钮"；兜底文字查找可覆盖"提问/我要提问/提个问题" |
| 答题数与官方对不上 | 手动答过/别的设备答过 | 点"同步已答"以官方记录为准 |
| 被平台禁言 | 倒计时太短、刷得太猛 | 倒计时 ≥20 秒；一天不要刷几百条；暂停几天再用 |
| 答完列表里现有的题就停住（旧版本现象） | 列表只加载了一批（默认 50 题），后续题目要滚到底才加载 | v2.7.0 起脚本会自动滚底加载下一批；若一直提示"没有更多题目"，说明该课程问答确实已穷尽 |

**调试入口**：浏览器 F12 控制台过滤 `智慧树` / `Alert:` / `子页面` 等关键词，脚本的每个关键决策都有 console.log。

| 调整提问风格 | 改 `generateQuestion` 里的 prompt 模板与采样参数 |
| 列表容器改版适配 | `.question-item` / `.question-content span` / `.qa-list-container` 等选择器（集中在各模块顶部，全局搜索替换） |
| 同步功能适配改版 | `.my-join-container` 的 `$data.questionList/noMore/loading` 字段名 |

### 10.3 调试技巧

- 详情页流程：`waitForAnswerButton` → `startChecking` 都有详细日志，按顺序排查。
- 父子通信：父页面控制台执行 `GM_getValue("zhsAnswerReport")` 看最近汇报；子页面搜"子页面模式"确认启动分流生效。
- 同步流程：控制台搜"已从官方"看同步条数；为 0 时检查 `.my-join-container` 是否还存在。
- 状态数据：控制台执行 `GM_getValue("questionsData")` 查看完整题库。

### 10.4 代码风格约定

- 所有注入 DOM 的 class 必须带 `zhs-` 前缀，防止污染页面样式或被页面样式污染。
- 所有定时器必须有退出条件（次数上限或超时）。
- 所有 GM 写入先读后写，避免多标签竞争丢数据（GM 存储操作是同步的，风险较低）。
- 新增长流程必须配防重入锁（参考 6.1）。
