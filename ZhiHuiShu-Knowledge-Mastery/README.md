# 智慧树 - 智能课程自动补全知识掌握度

自动补全智慧树课程「知识掌握度」：扫描掌握度页面的知识点，逐个进入测试题、AI 作答、提交，把遗漏点补成掌握。

**当前版本：v0.4.1**

## 防烧 token：做满 5 轮就放弃

**核心规则：同一个知识点做满 5 轮，掌握度仍不达标 → 直接放弃，当作完成，不再消耗 token。**

这个机制有三个要点，缺一不可：

1. **轮次持久化**（`roundLedger`）
   轮次记在 GM 存储里，键 = 知识点名。刷新页面、重启脚本、中途离开都不会清零。
   （早期版本只存在内存里，一旦流程重启就归零，上限就失效了。）

2. **放弃的项目会被永久排除**
   `isGaveUp()` 会在挑选目标时过滤掉做满轮次的项目。
   **这是最关键的一点**——否则它掌握度仍然 < 50%，下一轮又会被选中，无限循环烧 token。

3. **放弃的项目计入"已完成"**
   进度条把它算作完成，否则永远差几个、看起来像没跑完。
   面板会单独显示「已放弃 N」，让你知道哪几个是做不出来的。

实测（「相似度计算」连续 5 轮都是 40%）：

```
日志： 「相似度计算」已做 5 轮，掌握度 40% 仍未达 50%，已放弃并跳过（当作完成，不再消耗 token）
面板： 38 需考察 | 37 已完成 | 1 剩余 | 1 已放弃 | 50 免考
之后： 脚本再也没碰过「相似度计算」，直接去做下一个
刷新： 刷新页面后状态保留，不会被重新捡起来
```

轮次上限可在设置里调（`单点最多轮次`，默认 5）。脚本菜单另有两个命令：
- **查看作答轮次账本** —— 看每个知识点做了几轮、哪些已放弃
- **清空作答轮次账本** —— 想重新挑战那些做不出来的题时用

## 进度条：实时读取热力图

进度条**不是本地计数**，而是每次实时读取「掌握度热力图」里每个知识点的真实百分比：

- **分母** = 需考察项目数 = 知识点总数 − 免考数（例：88 − 50 = **38**）
- **分子** = 按模式判定"已完成"的项目数（含已放弃的）

每次切换模式都会**立即重新计算**并刷新进度条。

## 两种模式

| 模式 | 分子怎么算 | 挑什么做 |
| --- | --- | --- |
| **自动** | 掌握度 > 0（做过就算） | 按顺序做还没做过的（掌握度 0） |
| **查漏补缺** | 掌握度 ≥ 阈值（默认 50%） | 按顺序做所有低于阈值的项目，做完一遍后列表里再也看不到低于阈值的，自动停止 |

实测效果（38 个需考察）：

```
自动模式     : 38 / 38  (100%)   ← 全部都做过了
查漏补缺模式 : 33 / 38  (86.8%)  ← 33 个达标，5 个还低于 50%
```

## 安装使用

1. 安装 [ScriptCat](https://docs.scriptcat.org/) 或 Tampermonkey。
2. 新建脚本，粘贴 [`zhihuishu-knowledge-mastery.user.js`](zhihuishu-knowledge-mastery.user.js) 全文保存。
3. 打开课程的**知识掌握度**页面。
4. 展开面板「设置」，填入 **API Key**（可选改 API URL / 模型），点「保存设置」。
5. 选模式 → 点「开始」。

> API Key 只存在浏览器本地（`GM_setValue`），不会上传。

### AI 返回格式

脚本要求 AI 返回严格 JSON：

```json
{ "answers": [ { "index": 1, "answer": "A" }, { "index": 2, "answer": "ABD" } ] }
```

- **单选题** → 一个字母，如 `A`
- **多选题** → 多个字母，如 `ABD`
- **判断题** → 选项只有两个：`A`=对、`B`=错

解析器兼容 ```json 代码块包裹和前后带解释文字。

## 实测确认的完整链路

全部在调试 Chrome + 真实 Tampermonkey 环境实测：

```
掌握度页 li.item-box
  → 按颜色判定状态（origin 橙 / pink 粉 / gray 灰 / blue 免考）
  → 选中目标知识点，悬停（合成 mouseenter/mouseover/mousemove）
  → .el-popover.mastery-box-custom-popover 弹出
  → 点「提升掌握度」→ /exam?knowledgeId=...
  → 5 道题全部在 DOM 里（只显示当前题）→ 一次读完
  → 发 AI → 按答案点 input → 点「提交」
  → 必要时点「确认提交」
  → /pointOfMastery/... 分数页 → 点 .backup-icon 返回
  → 回到列表结算：达标 / 重做 / 换下一个
```

## 实测踩到的坑（都已在代码里处理）

### 1. 灰块不能直接点
必须让鼠标「摸」上去才亮出按钮。站点用原生 `mouseenter` 监听，脚本连发 `mouseenter`/`mouseover`/`mousemove` 三种合成事件即可。

### 2. `MouseEvent` 不能传 `view: window`
**在油猴沙箱里会直接抛异常**：`Failed to convert value to 'Window'`。沙箱的 `window` 和页面主世界的 `Window` 不是同一个对象。去掉 `view` 即可。
> 这个 bug 在主世界测试时不出现，**只有进沙箱才暴露**。

### 3. 选项字母的 class 不统一

| 题型 | 字母位置 |
| --- | --- |
| 多选题 | `.ccc`（`"A."`） |
| 单选题 | 无 class 的裸 `<span>`（`"A. "`） |
| 判断题 | **根本没有字母**，只有「对」「错」 |

**解决**：不读 DOM 里的字母，按选项顺序生成 A/B/C/D。判断题天然映射 A=对、B=错。

### 4. 单选按钮点 label 无效
`label.click()` 对 `el-radio` **完全无效**（`checked` 恒为 false），必须点 `input`。

### 5. checked 是异步更新的
点击后同一调用栈读到的是旧值，必须等两帧 + 120ms 再校验。

### 6. 点击是切换语义
已勾选的再点会取消，填写必须先判断状态（幂等）。

### 7. 验证码是常驻挂载的，会误报
`#captchaYidun` 是**宽度 1284 但高度 0** 的空容器，turing iframe 是 300×150 但 **`y = -1000000`**（挪到屏幕外）。只判断“宽度 > 0”会一直误报。正确判据是**有高度且在视口内**。

### 8. 知识点状态有 4 种，不是 2 种

| class | 颜色 | 含义 | 掌握度 |
| --- | --- | --- | --- |
| `origin` | 橙 `rgb(255,203,102)` | 掌握较好 | 80-100 |
| `pink` | 粉 `rgb(255,162,162)` | 薄弱点 | 1-59 |
| `gray` | 灰 `rgb(204,204,204)` | 遗漏点 | 0 |
| `blue` | 蓝 | 免考 | 不计入 |

### 10. 每项的精确掌握度**不用悬停就能批量读**（v0.4.0）

一开始以为必须逐个悬停读 popover，结果是错的——那样还会踩到**残留 popover** 的坑：
上一个浮层没关，读到的是上一个知识点的百分比（实测连续 5 个都读到同一个 60%）。

**实测真相**：每个知识点都有自己**常驻在 DOM 里**的 popover 节点（只是 `display: none`），
直接按顺序遍历即可一次读全：

```
「人工智能的基本概念 掌握度：60% 提升掌握度」
「 该知识点为免考知识点，不计入掌握度。 」
```

- 88 项的精确百分比**3ms 读完**
- popover 顺序与 `li.item-box` 顺序**完全一致**

另一个坑：颜色 class 的含义我最初搞反了，实测正确对应是：

| class | 颜色 | 图例 | 掌握度 |
| --- | --- | --- | --- |
| `green` | `rgb(140,229,162)` | 掌握较好 | ≥ 80 |
| `origin` | `rgb(255,203,102)` | **掌握一般** | 60–79 |
| `pink` | `rgb(255,162,162)` | 薄弱点 | 1–59 |
| `blue` | `rgb(143,208,255)` | 免考 | 不计入 |

### 9. 多选题只填上最后一个字母（v0.3.5 修复）

**症状**：AI 返回 `ACD`，结果只勾上了 `AD` 或单个 `C`，中间的字母凭空消失。

**原因**：`applyAnswers` 原本把所有选项**同步连点**。Vue 的响应式在两次点击之间来不及 flush，中间的选项被吞掉。

三轮重复对照实验（目标 `ACD`）：

| 方式 | 结果 |
| --- | --- |
| 同步连点 `input.click()` | `AD` / `AD` / `AD` ❌ |
| 逐个点 + 250ms 间隔 | `ACD` / `ACD` / `ACD` ✓ |
| 完整鼠标事件链 + 80ms | `ACD` / `ACD` / `ACD` ✓ |

**修复**：改成串行填写——每次点击后等 2 帧 + 120ms（`OPTION_GAP`），逐题校验，最多重试 3 轮（`VERIFY_TRIES`）。

效果对比（同一知识点「数据规约」）：

```
修复前：未完全勾上的题：2(ABCD)，4(ABCD)，5(AB) → 已填写 2/5 → 掌握度 40%
修复后：已填写 5/5                              → 掌握度 100%
```

## 限制

1. **腾讯防水墙**：触发滑块时 `isTrusted` 无法伪造，脚本会检测到并暂停，等手动过验证。
2. **答错不涨分**：需要答对才计入掌握度；查漏补缺模式靠多轮重做达标。
3. **多选题答案要给全**：AI 只返回一个字母而该题是多选时，站点会判定“未作答”。

## API 配置

默认值指向 GLM（`https://api.gpt.ge/v1/chat/completions` + `glm-4-flash`）。
**注意：API Key 必须和 API 地址属于同一个服务商**——把 gpt.ge 的 Key 填到 DeepSeek 地址（或反之）会返回 401「无效的令牌」。

各服务商实测可用的组合：

| 服务商 | API URL | 模型 |
| --- | --- | --- |
| GPT.GE 中转（默认） | `https://api.gpt.ge/v1/chat/completions` | `glm-4-flash` |
| DeepSeek 官方 | `https://api.deepseek.com/v1/chat/completions` | `deepseek-flash` / `deepseek-chat` |

> 仓库**不内置任何 API Key**（安全红线）。Key 只存在浏览器本地 `GM_setValue`。
