# 智慧树 - 标题状态显示器

纯执行脚本，**无 UI**。把智慧树各页面的标签页标题改成「当前所在位置 - 用户名」，多开标签时一眼就能认出当前在哪。

**当前版本：v1.2.0**

## 效果

| 当前页面 | 标签页标题 |
| --- | --- |
| 学生首页 | `首页 - 李侠` |
| 问答（列表 / 详情 / 我的参与） | `问答 - 李侠` |
| 见面课（列表 / 详情） | `见面课 - 李侠` |
| 作业考试 / 作业结果 | `作业 - 李侠` |
| 直播 / 视频回放 | `直播 - 李侠` |
| 官网 | `官网 - 李侠` |
| **未登录**（读不到姓名） | `首页` / `问答` / `官网`（只有状态，不带 `-`） |

**不显示课程名** —— 页面里本来就有课程名，标题里重复没有意义。

## 安装使用

1. 浏览器安装 [ScriptCat](https://docs.scriptcat.org/) 或 Tampermonkey。
2. 新建脚本，把 [`zhihuishu-title-status.user.js`](zhihuishu-title-status.user.js) 全文粘贴保存。
3. 打开任意智慧树页面，标签标题即会变化。

脚本菜单里有「刷新标题状态」可手动触发一次。

| 域名 | 判定 | 显示 |
| --- | --- | --- |
| `onlineweb.zhihuishu.com` | 路径 `/onlinestuh5` | 首页 |
| `onlineweb.zhihuishu.com` | 其他 | 在线学堂 |
| `qah5.zhihuishu.com` | 任意（列表/详情/我的参与） | 问答 |
| `onlineexamh5new.zhihuishu.com` | `#/webExamList` 与 `#/webExamList/checkHomework/...` | 作业 |
| `stuonline.zhihuishu.com` | 含 `/teachMeeting` | 见面课 |
| `stuonline.zhihuishu.com` | 含 `/stuLearnReport` | 成绩分析 |
| `lc.zhihuishu.com` | 任意（直播/回放） | 直播 |
| `www.zhihuishu.com` | `/` | 官网 |
| 其他子域 | — | 兜底用子域名 |

**识别不了的页面不改标题**，保持站点原始标题。

## 用户名从哪来

按优先级三级兜底：

1. **`CASLOGC` cookie**（首选）：智慧树 CAS 登录票据，域为 `.zhihuishu.com`，**所有子域都能读到**。内容是 URL 编码的 JSON，取 `realName` 字段（`username` 是一串哈希，不能用）。
2. **DOM 节点**：`.user-logo_name`（首页顶部）等选择器。
3. **GM 存储缓存**：前两者都读不到时用上次成功的名字。

读不到时**只写状态**，不显示占位符。

## 踩过的三个坑（都已在代码里处理）

### 1. 问答页的「用户名」其实是助教账号

`qah5` 页面上有个 `.user-name` 元素，看起来像用户名，实际内容是 **「课程问答小助手」**（智慧树官方服务助教账号），**不是当前登录用户**。

脚本用黑名单（`小助手` / `官方` / `助教` 等）把它排除，避免标题显示错人。

### 2. 直播页把全局 `Map` 覆盖了

`lc.zhihuishu.com` 上有老代码重写了全局 `Map`，生成的实例**只有 `put()`，没有 `has()` / `get()`**：

```js
function Map() { var mapObj = {}; this.put = function (k, v) { ... }; }
```

脚本原本用 `new Map()` 做内存兜底，结果在直播页初始化时抛 `TypeError: mem.has is not a function`，**整个脚本不执行**（表现就是直播页标题不变）。

修复：改用数组实现键值存储，不依赖任何可能被污染的全局内置对象。

### 3. 首页是轮播墙，没有唯一的「当前课程」

首页同一时刻多门课都在 `.slide-item-current` 里，强行取课程名会取到别的课。所以脚本**完全不读课程名**，只标位置。

## 技术要点

- `@run-at document-start`，尽早接管标题。
- **同步拦截 `document.title`**：站点若用 JS 改标题，赋值后在同一个调用栈内被改回，用户几乎无感知（详见下方「为什么标题会晚几秒才变」）。
- 监听 `hashchange` / `popstate` 处理 SPA 路由切换。
- DOM 变化合并成 120ms 防抖。
- 前 5 秒每 500ms 兜底（等用户名异步渲染），之后降为每 3 秒。
- 不创建任何 DOM、不注入样式，唯一副作用是改写 `document.title`。

## 为什么标题会晚一点才变

实测首页时间线（优化前）：

```
104ms  脚本注入
556ms  写入「首页 - 李侠」          ← 已经正确了
880ms  站点把它改成「学生首页_在线学堂_智慧树」  ← 被覆盖
977ms  脚本检测到，写回「首页 - 李侠」
```

**原因不是脚本慢，而是站点自己会抢标题。** 它在 `app.c5e24df1.js` 里通过 Vue 的标题处理函数执行 `document.title = '学生首页_在线学堂_智慧树'`。

v1.2.0 的做法：在 `Document.prototype` 上替换 `title` 的访问器，站点任何一次赋值都会在**同一个同步调用栈内**被改回，不再有可见的闪现。

> 注意：不能把访问器装在 `document` 实例上——站点代码走原型链，实例属性会被绕过（实测无效）。必须改 `Document.prototype`。

另外，「打开页面到标签显示正确标题」这段时间里，还有一部分**本来就是页面自身的加载耗时**（Vue 异步接口拉用户信息和课程数据）。脚本在 `document-start` 就执行，能做的优化仅限于“不被站点覆盖”，站点数据没回来之前用户名本身也拿不到。
